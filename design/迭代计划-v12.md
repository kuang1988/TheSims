对比门派链尚有 `entry` / `war`；薄链 **无 entry**，开端视觉偏空。

### 1.2 薄链配图覆盖（主债）

口径：全库 `chain ∈ {escort,master,force}`（含旧事件 + p16/p17）。

| 链 | 事件数 | `CLIMAX_BY_EVENT_ID` 已绑 | 约估 id+标题皆无图 | `imp≥4` 无图（P0） |
|----|--------|---------------------------|--------------------|--------------------|
| escort | ~39 | ~6 | 大半 | ~5 |
| master | ~37 | ~6 | 大半 | ~6 |
| force | ~33 | ~5 | 大半 | ~3 |
| **合计** | **~109** | **~17（≈16%）** | **~75** | **~14** |

**典型未绑高潮（imp≥4，须进映射表）**

| 链 | 事件意向（id 示例） | 建议桶 |
|----|---------------------|--------|
| escort | `escort_p16_betrayal` / `jade` / `bounty` / `secret` | mid 或 finale |
| master | `master_p16_betray` / `duel` / `vow`；`p17_yinshi_*` | mid / finale / relation 慎用 |
| force | `force_p16_bridge` / `sect` / `beast` | mid / finale |

**误绑风险**：标题含「仇敌」的镖路事件可能落入 `c_relation_enemy`，应优先 `c_escort_*`（id 映射优先于正则）。

### 1.3 事件 / 抉择与插图契约

| 规则（现状） | 含义 |
|--------------|------|
| `artUrlForLog` | 对 `kind === 'choice'`（「·去向」）**故意不插图** |
| 可见图挂在 | **事件正文**（`eventId` / 标题） |
| 产品含义 | 重大抉择要出图 → 必须保证 **该事件行** 有 climax 绑定，而非给选项行单独出图 |

薄链 `needsChoice && imp≥3` 无事件图者仍多；全局 `imp≥4` 无图约百余——本版 **薄链优先**，全局只做「能挂旧桶则挂」，不出一事一图。

### 1.4 立绘体验债

- 女选少林气质 / 男选峨眉气质时，图与自称门派不一致（回落可跑，但不「补齐」）。  
- 本版 **P0 补两张立绘**，并去掉或收紧回落说明（单测与 UX 文案同步）。

## 2. 本阶段战略

### 2.1 三柱目标

| 目标 | 玩家体感 | 抓手 |
|------|----------|------|
| **薄链看得见** | 镖/师/力关键劫难与终局旁有图 | 扩 `CLIMAX_BY_EVENT_ID` + 修正误绑 |
| **抉择不空镜** | 半自动重大岔路前后事件页有图 | 事件行绑定；不改 choice 行策略 |
| **立绘矩阵完整** | 九原型 × 两性均有独立脸 | `p_f_shaolin`、`p_m_emei` 出图入库 |

### 2.2 设计原则

1. **先映射、后出图**：现有 27 高潮桶能覆盖的，禁止新开同主题文件  
2. **id 映射 > 标题正则**：薄链重要事件必须进 `CLIMAX_BY_EVENT_ID`  
3. **抉择图 = 事件图**：不给选项行插图；保证父事件有绑  
4. **立绘补洞优先于新原型**：本版只补矩阵洞，不开第十原型  
5. **审计可回归**：资产覆盖进 `npm run` 脚本，防再漂  

### 2.3 明确不做

| 不做 | 原因 |
|------|------|
| 再 +100 事件灌水 | 本版是视觉与映射 |
| 每个抉择选项一张图 | 与现阅读器契约冲突、成本炸 |
| 实时文生图 API | 静态资产 |
| 改死因 / 模拟器核心 | 规格外 |
| 强制身份变脸 | 出生锁定契约仍在；仅补可选脸 |

## 3. 产品规格

### 3.1 审计脚本（P0）

落地 `scripts/asset-climax-audit.mts`（或并入 `data-ref-audit`），建议 `npm run asset-audit`：

1. `ALL_CLIMAX_KEYS` ↔ `public/assets/climax/*.webp` 一一对应  
2. `DEATH_TAG_FINE_KEY` ↔ `ending/e_death_*.webp`  
3. `PORTRAIT_ARCHETYPES` × `{m,f}` ↔ 文件存在（豁免表可配置，本版结束后豁免应空）  
4. 按 chain 输出：事件数 / id 已绑 / imp≥4 未绑清单  
5. 抽样：标题正则命中键 ≠ 期望链桶时告警（如镖路→仇敌桶）  
6. **硬失败**：磁盘缺 manifest 键；**软报告**：薄链 imp≥4 未绑条数（本版 DoD 要求清零）

### 3.2 薄链 / 事件映射补齐（P0）

| 项 | 规格 |
|----|------|
| 薄链 `imp≥4` 无图 | → **0**（或 ≤2 书面豁免） |
| 薄链 `imp≥3` 且 `needsChoice` | 至少 **70%** 事件行可解析到 climax |
| 误绑修正 | `escort_p16_revenge` 等 → `c_escort_*` |
| 扩映射量 | 约 **+40～60** 条 `CLIMAX_BY_EVENT_ID`（复用 mid/finale/entry） |

### 3.3 抉择体验（P0）

| 项 | 规格 |
|----|------|
| 半自动抽测 | 镖 / 师 / 力各 1 局：重大抉择暂停前一页或当页事件有旁图 |
| 文案 | 不在选项上叠图；可选在抉择 sheet 旁显示「本段插图」（若易做，P1） |
| choice-audit | 仍保持空气重大 = 0（本版不改抉择效果，只绑图） |

### 3.4 立绘补齐（P0）

| 文件 | 气质 |
|------|------|
| `portrait/p_f_shaolin.webp` | 女僧门弟子：灰衣/戒疤或念珠符号，沉静 |
| `portrait/p_m_emei.webp` | 男峨眉外门/客卿气质：青布、剑穗，清峻（勿抄女峨眉） |

同步：

- `normalizePortraitLook` / `portraitPoolForGender`：纳入真实文件，去掉对该二者的强制回落（或仅作缺文件兜底）  
- `assetResolve` 单测：两键可解析  
- 入世立绘选择器：少林女、峨眉男可选且预览正确  

### 3.5 配图增量（P1，按需）

若映射后仍觉「开端空」：

| 新键 | 用途 |
|------|------|
| `c_escort_entry.webp` | 揭贴/接镖/出城 |
| `c_master_entry.webp` | 拜山/跪求/初见师父 |
| `c_force_entry.webp` | 入武馆/码头第一拳 |

原则：仅当现有 mid 无法体面表达「起拍」时才出；出则写入 `ALL_CLIMAX_KEYS` + 事件起拍 id。

**P2（可选）**：全局重大无图事件，只挂最近似旧桶（sect/love/civic…），不出新文件。

### 3.6 文生图流程（继承 v5）

```
冻结附录清单（立绘 2 + 可选 entry 3）
  → 出图 webp
  → public/assets + docs 构建同步
  → manifest / pool / 单测
  → 映射表合入同一里程碑
```

风格：宋元水墨纸色、半身立绘、高潮宽幅情节瞬间；禁现代物与霓虹。
