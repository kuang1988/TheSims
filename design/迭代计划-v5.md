## 2. 本阶段战略

### 2.1 双柱目标

| 目标 | 玩家体感 | 抓手 |
|------|----------|------|
| **人物有脸** | 入世/局中/结算能认出「这一生是谁」 | 立绘槽：性别 × 原型（门派/魔/匪/凡尘…） |
| **高潮有画** | 一生回顾与分享图能看到「那一仗/那一别」 | 高潮卡（链×节拍）+ 终局卡（死法精标 / finale） |

### 2.2 文生图前置原则（本版硬约束）

1. **先清单、后出图**：无绑定表（事件 id / 死标 / 原型）的图不入库  
2. **分桶不混用**：立绘 = 稳定身份；高潮卡 = 叙事节拍；终局卡 = 死法/收束情绪  
3. **主题复用优于一事一图**：同类守山血战共用一张，避免资产爆炸  
4. **运行时回落**：缺图时用链默认图 / 文字态，不白屏  
5. **不阻断游玩**：图片失败不影响推进与结算  

### 2.3 明确不做

| 不做 | 原因 |
|------|------|
| 为每个 NPC 名单独立绘 | 池子共用、性价比低；道侣用关系槽+通用脸 |
| 每个 importance≥4 事件独图 | 200+ 不可维护 |
| 实时文生图 API 进主路径 | 延迟/成本/合规；本阶段静态资产 |
| 3D/Live2D | 规格外 |
| 用配图掩盖叙事断链 | 连贯仍靠 Phase 10 规则 |

## 6. 分柱细则

### 6.1 立绘（Portrait）

**驱动维度（MVP）**

```
gender(m|f) × archetype(
  huashan|wudang|shaolin|emei|gaibang|
  demon|bandit|civic|wanderer
)
```

- 出身（农户/商贾/书香…）作 **服装/场景气质提示词**，不拆独立绘文件  
- 传说称号（盟主/教主/天下无敌…）作 **角标层或后期变体**，不阻塞 MVP  
- NPC（苏晚晴等）**不单独立绘**；道侣/师父用通用「关系侧脸」可选（P2）

### 6.2 高潮卡（Climax）

- 按 **chain × beat** 出图：`entry | mid | war | finale | echo`  
- 运行时：用高光对应日志的 `title`/事件 id 映射到主题卡；映射不到则链默认 `mid`  
- 禁止为每个 trait_ 事件单独出图  

### 6.3 终局卡（Ending）

- **优先** `FINE_DEATH_TAGS`（22）→ 结算头图 / 分享底图  
- 其次 `*_finale` / `civic_*_late` / `act2_late_home` / `rel_*_fate`  
- 死法精标与长文案并存：图跟精标，字跟长文案  

### 6.4 命名约定（冻结）

```
public/assets/
  portrait/p_{m|f}_{archetype}[_vN].webp
  climax/c_{chain}_{beat}[_vN].webp
  ending/e_death_{fineKey}.webp
  ending/e_finale_{eventId}.webp
```

例：`p_f_emei.webp`、`c_sect_war.webp`、`e_death_sect_martyr.webp`、`e_finale_huashan_finale.webp`。

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 出图风格不统一 | 统一提示词骨架（武侠水墨/版画风择一）；固定种子与负向词 |
| 资产体积撑爆 Pages | webp + 适当分辨率；立绘≤512 边；按需懒加载 |
| 映射不准导致「图不对戏」 | 绑定表审；缺省回落纯文字；禁止乱套 |
| 生成成本失控 | 主题复用；MVP 先 死标+立绘再高潮 |
| 与现有排版冲突 | 结算仍一书一页；图作辅，不抢死法标题 |

## 附录 C — 文生图提示词骨架（统一风格，择一锁定）

**建议风格（避免紫霓虹/奶油杂志风）**：水墨淡彩武侠插画，纸纹，克制用色，半身或场景叙事，无现代物，无文字水印。
