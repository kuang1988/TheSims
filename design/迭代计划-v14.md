## 0. 一句话

> 终局要像句号，不像断章——死之前至少有一年能感知的「事将至」，突破/横死出口必须接得上前文，结算前给一屏告别。

---

## 1. 玩家体感（本版立项证据）

| 体感 | 说明 |
|------|------|
| **突兀** | 实机约 12 局：每次终局都像被掐断；典型「上一次在突破，下一次就死亡」 |
| **无告别** | `died` 后立刻进结算屏；人生书里的死亡 climax 是死后才翻到 |
| **与审计错位** | 现有 `death-audit` 管「叫什么死 / 是否贴身份」，**不管**「死前有没有铺垫年」——门槛全绿仍可很突兀 |

> Phase 8 解决的是「死于非命」粗标；本版解决的是 **节奏与因果链**，不是再拆标签。

---

## 2. 根因（代码层，按冲击排序）

| # | 根因 | 证据抓手 | 玩家怎么感到 |
|---|------|----------|--------------|
| 1 | **事件同岁立刻 `effects.death` → 当年 `ended`** | `simulator.advanceYear`：解析出 `deathMsg` 即返回，无「预警年」 | 抉择页一关，人生结束 |
| 2 | **`death_breakthrough` 与突破叙事脱钩** | `phase7Events`：仅 `minRealmIndex: 3` + 无 `broke_through_safe`；**不要求** `broke_through` / `inner_risk` | 平时闭关/突破与「破境之劫」像两件事；或刚破境又抽到劫 |
| 3 | **一批 `death_*` 是单拍出口** | 赐死 / 情劫 / 毒夜 / 殉道 / 突破等：一拍抉择即死或活 | 没有「再见 → 变故 → 终局」多拍 |
| 4 | **系统死（寿元/体魄）无仪式** | `checkDeath` → `flavorLifespanDeath` / `flavorBodyDeath`；软保耗尽后直接陨落句 | 属性归零像 bug，不像收束 |
| 5 | **UI 无临终关** | `App.finish` → `setScreen('ending')` | 情绪来不及落地 |

**明确不是本版主因**：death-audit 失败、缺 climax 图、精死标折叠（已交付且报告绿）。

## 3. 范围界定

### 3.1 本版要什么（DoD 语言）

玩家任意一局结束时，应能复述至少一句：

> 「死之前发生过 ___（预警/余波/诀别），所以 ___（死因）说得通。」

量化门槛见 §6。

### 3.2 三柱

| 柱 | 玩家体感 | 抓手 | 优先级 |
|----|----------|------|--------|
| **A. 出口接链** | 破境死、横死出口能指回前文旗/事件 | 条件收紧、`queueEvent` 预警拍、危险出口降权 | **P0** |
| **B. 濒死余韵** | 高重要致死不全是「同岁一拍完结」 | 临终队列 1～2 年 / 同岁第二拍诀别；系统死前仪式事件 | **P0** |
| **C. 告别结算** | 先看见「这一生怎么落幕」，再进条形结算 | 临终屏或自动翻到死亡 climax 再 `ending` | **P1** |

### 3.3 明确不做

| 不做 | 原因 |
|------|------|
| 重拆 `deathEndingTags` / 再调寿终占比 KPI | v2/v4 已交付；本版不测「叫什么」而测「有没有铺垫」 |
| 大改 lifespan / 体魄衰减公式 | 节拍问题，不是数值平衡专项 |
| 为每个死亡新开玩法系统 | 战略禁止 |
| 空气扩池凑字数 | 连贯优先于体量 |
| 实时文生图 / 每死法新图矩阵 | 配图遮不断链；缺图另开资产单 |

## 4. 设计原则

1. **预警年优先于软保命**：能「拖死」不如「让玩家看见死将至」。  
2. **突破死必须吃突破债**：`death_breakthrough` 应要求近期突破风险旗（如 `inner_risk` / `broke_through`），或由闭关链 `queueEvent` 唤出；禁止「境界够了就随机暴毙」。  
3. **重要死 ≥ 两拍**：importance≥5 且含 `death` 的出口，默认「预警/余波 → 终局抉择」或「死局 → 同岁诀别日志」。  
4. **系统死也有仪式**：寿元将尽 / 体魄三次软保后，优先播临终事件，再允许 `checkDeath` 收束。  
5. **审计要能抓突兀**：新指标进 `death-audit`（或旁路脚本），否则本版无法验收。  
6. **复用现成多拍**：关系线「再见→变故→终局」、`aftermath_near_death`、`trySparePrematureDeath`——扩展，不另起炉灶。

## 5. Sprint 计划

### Sprint E0 — 冻结突兀基线（0.5d）

| 项 | 交付 |
|----|------|
| 批跑 / 手工 20～40 局 | 记录：致死事件 id、前一岁日志 kind、是否有前置旗、是否同岁首见致死 |
| 出口清单 | 冻结 Phase7 `death_*` + 其它高频 `effects.death` 表（id / 条件 / 是否可 spare） |
| 指标草案 | 「无前置旗致死」「致死前 1 年内无相关 tag/旗」「突破死无 `inner_risk|broke_through`」占比 |

**出门**：基线数字写进本文件附录 A（可本地报告，gitignore）。

---

### Sprint E1 — 破境接链（P0，1d）【对应用户原话】

| 改动 | 说明 |
|------|------|
| 收紧 `death_breakthrough` 条件 | 要求 `anyFlags: ['inner_risk','broke_through', …]`（择优）；保留 `forbidFlags: broke_through_safe` |
| 正向链 | 闭关 / 内力升级 / 灵犀突破等成功或带风险的选择 → `queueEvent('death_breakthrough')` 或 `addFlag:'inner_risk'`，而不是只靠随机池 |
| 权重 | 无债时 weight→0 或从池移除；有债时再允许出现 |
| 文案 | 劫文应对上「此前闭关/冲关」痕迹（logExtra 或条件文案） |
| 高潮 | `CLIMAX_BY_EVENT_ID` 补 `death_breakthrough`（若缺），避免死页无图放大突兀 |

**验收**：带 `broke_through`/`inner_risk` 的局，破境劫可读作续章；无债局几乎摸不到「突然破境死」。

---

### Sprint E2 — 危险出口多拍化（P0，1.5d）

按出口清单逐条改，优先高频 / 高冲击：

| 模式 | 适用 | 做法 |
|------|------|------|
| **预警拍** | 赐死、仇杀、毒、门派浴血 | +1 年 `queueEvent` 预警（风声/征兆），次年才开致死抉择 |
| **同岁余韵** | 已选死、需情绪落地 | 死后追加一条非交互 `log`（诀别/余响），再 `ended`（若引擎需小改：允许同岁双日志） |
| **软出口先** | 可活可死 | 默认倾向「伤重 / 余波旗」；致死选项需更高倾向或二次确认语义（文案层，不做二次弹窗系统） |

**复用范本**：徒弟背叛链、情缘余波多拍。

**不做**：把所有 death 改成不可死（保命过多会毁终局）。

---

### Sprint E3 — 系统死仪式（P0，1d）

| 路径 | 做法 |
|------|------|
| 寿元 | `age >= lifespan - 2` 时优先 `queueEvent` 临终类（托孤/立嘱/坐化前夜）；耗尽岁播仪式后再 `flavorLifespanDeath` |
| 体魄 | 软保将尽或 `aftermath_near_death` 后，强制或高权临终事件，再允许体魄死 |
| 文案 | 系统死日志须引用近 3 年高潮/身份一句（可模板填空），避免裸「陨落」 |

---

### Sprint E4 — 告别再结算（P1，0.5～1d）

| 方案（择一为主） | 说明 |
|------------------|------|
| **A. 临终薄屏** | `died` → `farewell` 屏（死亡文案 + 主图 +「阅尽此生」）→ `ending` |
| **B. 书页先翻** | 自动打开人生书并定位死亡 climax，确认后再进条形结算 |

约束：不重做整站 ending；分享卡仍从 ending 出。

---

### Sprint E5 — 突兀审计 + 回归（P0，0.5d）

| 项 | 门槛（建议，E0 后可微调） |
|----|---------------------------|
| `npm test` | 全绿 |
| `npm run death-audit` | 旧门槛不回退 |
| **新**：无前置旗的「随机破境死」 | ≈ **0**（样本 ≥30） |
| **新**：致死前 0～2 年内有相关旗/预警事件 | ≥ **70%** 局 |
| `choice-audit` / `sect-fork` | 不回退 |
| 手工 | ≥5 局含突破债路径，终局可复述「预警→死」 |

## 6. 验收（产品语言）

- [ ] 突破相关终局：能指回闭关/冲关/心魔债，而不是「境界到了随机死」  
- [ ] 任意横死出口：死前至少 1 拍预警或同岁诀别，不「抉择完黑屏结算」  
- [ ] 寿终/体魄死：有仪式事件或模板收束句  
- [ ] 结算前有告别（屏或书页）  
- [ ] 突兀类审计指标进脚本且门槛达标  
- [ ] README / `design/README` 指向本版；计划标已交付时改状态
